# PDP-11 Unix on both Picos: direct floating point on RP2040

Fresh RP2040 physical-board results after enabling direct FP11 execution. RP2350 figures are the earlier same-day hardware results; its firmware is unchanged. General Thumb-1/Thumb-2 code applies to all guest programs, without benchmark recognition.

| Test | Pico W / RP2040, 200 MHz | Pico 2 W / RP2350, 150 MHz | Real PDP-11/70 reference |
|---|---:|---:|---|
| Compile / assemble / link / run | 11.59 s | 11.07 s | No matched measurement |
| Processes / pipes / file operations | 7.72 s | 6.70 s | No matched measurement |
| Text tools / sorting / pipelines / editing | 10.17 s | 10.87 s | No matched measurement |
| Repeated utilities / filesystem reads | 18.81 s | 26.81 s | No matched measurement |
| **Complete four-phase Unix suite** | **48.29 s** | **55.44 s** | No matched measurement |
| Sieve, normalized to 10 passes | **0.840 s** | **0.999 s** | **1.52 s**, historical C/Unix V6 |
| Double-precision Whetstone | **241.1 KWIPS** | **489.3 KWIPS** | No matched C/Unix measurement |

Both boards pass the complete Unix workload with checked outputs. The new RP2040 runs have zero lost console input and zero dropped clock ticks. Phase times exclude setup and source transfer; each full suite is one run, not a statistical average.

Both Whetstone builds now run 3,000 KWhetstones, three times, with matching X=9311/10000. RP2040 host times are 12.443447, 12.438980, 12.441653 s (median 12.441653 s); RP2350 median is 6.131621 s. The earlier RP2040 guest-interpreter result was 5.799 KWIPS on shorter 100-KWhetstone runs; direct FP11 gives about 41.6 times that throughput. This is a measured Whetstone gain, not a promised multiplier for every floating-point program.

Sieve runs 100 passes three times, always returning 1,899 primes. Median time is normalized to ten passes. Against BYTE's historical 1.52-second result, RP2040 has 1.81 times and RP2350 1.52 times the throughput for this test. Different compilers and systems limit the comparison. No matched real-11/70 timing exists here for the complete Unix suite or C/Unix Whetstone; no scaled whole-machine estimate is presented.

The RP2040 previously trapped FP11 instructions into Mini-Unix's guest software interpreter. The ARM floating-point library was not involved. It now executes DEC F/D operations directly using exact integer pairs, with Thumb-1 multiplication and quotient loops and common normalization/rounding/shift helpers in SRAM. D-format retains its 56-bit significand. The kernel saves FPS and all six accumulators across process switches, clears live state on exec, and delivers floating exceptions as signal 8. Install BOTH the new normal firmware and Mini-Unix pack for this support.

The general 63 KB lossless compressed/deduplicated write overlay and 255 unique-record limit remain. The complete 56 KB guest, panel and runtime fonts remain enabled. Standard program size is 197,528 bytes; code SRAM is 49,136 bytes with 248 bytes free beyond the compiler's reserved stacks/windows. The native-built kernel ends at 22,700 with 852 bytes reserved below the swap stack.

Validation: 22,528 native arithmetic checks; both DEC JFPAA1/JFPBA0 diagnostics with zero errors; independent math/precision/conversion checks; all six accumulator/FPS states preserved through fork and blocking pipes; exec resets state; divide-by-zero delivers signal 8. A deliberately wrong quotient fails the fixture, and the old kernel fails the state-preservation check. All execution ran on the physical RP2040.
