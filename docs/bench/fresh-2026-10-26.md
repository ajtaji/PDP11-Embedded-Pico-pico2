# PDP-11 Unix on both Picos: fresh hardware results

Fresh tests on physical boards, 26 October 2026. Pico W runs Mini-Unix at 200 MHz; Pico 2 W runs Unix V6 at 150 MHz. General Thumb-1/Thumb-2 optimizations apply to the emulator; there is no benchmark recognition.

| Test | Pico W / RP2040 | Pico 2 W / RP2350 | Real PDP-11/70 reference |
|---|---:|---:|---|
| Compile / assemble / link / run | 11.55 s | 11.07 s | No matched measurement |
| Processes / pipes / file operations | 7.72 s | 6.70 s | No matched measurement |
| Text tools / sorting / pipelines / editing | 10.16 s | 10.87 s | No matched measurement |
| Repeated utilities / filesystem reads | 18.72 s | 26.81 s | No matched measurement |
| **Complete four-phase Unix suite** | **48.15 s** | **55.44 s** | No matched measurement |
| Sieve, normalized to 10 passes | **0.835 s** | **0.999 s** | **1.52 s**, historical C/Unix V6 |
| Double-precision Whetstone | **5.80 KWIPS**, software floating point | **489.3 KWIPS**, emulated FP11 | No matched C/Unix measurement |

Both boards passed all Unix phases, with checked outputs, zero lost console input and zero dropped line-clock ticks. Phase times exclude setup and source transfer. This is a single fresh complete suite per board, not a statistical average.

The RP2040 capacity failure is fixed with a general lossless compressed/deduplicated RAM overlay. Its Mini-Unix kernel now provides real pipes; swap, exit and wait consistently use process slots. The overlay remains finite: 63 KB and 255 unique records, with sharing and raw fallback.

Sieve was run three times, 100 passes each, always returning 1,899 primes. Median host time is normalized to ten passes. Against BYTE's historical 1.52-second PDP-11/70 result, that is about 1.82x the throughput on RP2040 and 1.52x on RP2350 for this test. Different systems and compilers limit that comparison; it does not prove that every Unix workload is faster than an 11/70.

Whetstone also used three fresh runs: 100 KWhetstones per run on RP2040, 3,000 on RP2350. Median host times were 17.243 s and 6.132 s; checked numerical results were X=7598/10000 and X=9311/10000 respectively. RP2040's software floating point is much slower. The result printer explicitly converts the final double for the old printf integer format.

There is no matched real-11/70 timing for this complete Unix suite, so no Sieve-scaled guess is presented as a full-machine measurement.
